\par API (Application Programming Interface) --- программный интерфейс, обеспечивающий взаимодействие между компонентами программного обеспечения.
\par RGB (red, green, blue) --- цветовой формат машинной графики, основанный на смешении компонентов красного, зелёного и синего цветов.
\par WWW (World Wide Web) --- всемирная паутина, система взаимосвязанных гипертекстовых документов.

\section{ТРЕБОВАНИЯ К СОДЕРЖАНИЮ ПОЯСНИТЕЛЬНОЙ ЗАПИСКИ}

Выпускная квалификационная работа (ВКР) программиста должна иметь прикладной и/или научно-исследовательский характер. Если работа имеет прикладной характер, в ней должны быть:
\begin{itemize}[label=-]
	\item представлена постановка задачи и техническое задание на разработку ПО;
	\item обоснована актуальность работы, выполнен обзор аналогов разрабатываемого ПО;
	\item разработана архитектура ПО для решения поставленной задачи;
	\item разработано ПО согласно выбранной архитектуре;	
	\item обеспечена информационная безопасность разработанного ПО;
	\item проведено тестирование разработанного ПО и оценка его метрологических характеристик;
	\item приведено руководство пользователя.
\end{itemize}

Если работа имеет научно-исследовательский характер, в ней должны содержаться:
\begin{itemize}[label=-]
	\item научная новизна предложенных методов и алгоритмов;
	\item актуальность работы;
	\item постановка задачи в словесно-формульном виде;
	\item положения, выносимые на защиту;
	\item математическая модель исследуемой предметной области;
	\item описание предложенных математических методов и алгоритмов решения поставленной задачи (в виде формул, блок-схем);
	\item результаты разработки ПО для решения поставленной задачи;
	\item результаты проведения вычислительных экспериментов на реальных и/или модельных данных.
\end{itemize}

\subsection{Тематики выпускных квалификационных работ}

В ВКР обязательно должна присутствовать разработка ПО на каком-либо языке программирования. Обязательным результатом выполнения ВКР является готовое к использованию ПО.
% Использование только лишь языков разметки не считатся разработкой ПО.
ВКР должна соответствовать одной из следующих тематик:
\begin{enumerate}[label=\arabic*.]
	\item Системное программное обеспечение (драйверы, утилиты).
	\item Прикладное программное обеспечение (редакторы, мультимедийные приложения).
	\item Сетевое программное обеспечение.
	\item Сервис-ориентированное программное обеспечение.
	\item Разработка веб-приложений.
	\item Разработка мобильных приложений.
	\item Разработка нейросетевых приложений, в том числе с использованием глубокого обучения.
	\item Разработка приложений искусственного интеллекта: компьютерное зрение, обработка естественного языка, обработка звука, генетические алгоритмы и др.
	\item Разработка приложений для решения задач математической логики и автоматизированного рассуждения.
	\item Математическое программное обеспечение для решения задач моделирования различных процессов.
	\item Разработка методов и алгоритмов вычислительной математики.
	\item Разработка систем поддержки и принятия решений, а также нечёткой логики.
	\item Разработка лексических и синтаксических анализаторов, компиляторов, интерпретаторов.
	\item Разработка графических приложений, алгоритмов проективной геометрии.
	\item Разработка игровых приложений.
	\item Разработка программного обеспечения для микроконтроллеров, ПЛИС, встраиваемых систем.
	\item Разработка программного обеспечения для анализа данных.
	\item Разработка баз знаний, советующих и рекомендательных систем.
	\item Разработка программного обеспечения для решения задач оптимизации, планирования, распределения, прогнозирования.
	\item Разработка программного обеспечения с использованием параллельных вычислений.
	\item Разработка программного обеспечения для автоматизации
	технологических процессов.
	\item Разработка программного обеспечения для решения задач информационной безопасности.
\end{enumerate}

\subsection{Структура и содержание пояснительной записки}
В работе не допускается наличие общеизвестного теоретического материала, доступного в литературе или в интернете. Это снижает процент оригинальности работы, замедляет процедуры нормоконтроля и проверки заимствований. Достаточно вставить в текст работы ссылку на необходимый литературный источник. Допускается добавлять в работу теоретические сведения только в том случае, если последующие изложение без них невозможно. Не допускается включение теоретических сведений по основам программирования (любой парадигмы), описанию общеизвестных технологий и языков программирования,  а также других базовых знаний,  полученных в процессе обучения.

Во { \bf введении } должно быть написано о том, какое место занимает решаемая проблема в области информационных технологий. Например, требуется разработать алгоритм визуализации фигур вращения. Значит, нужно собрать из открытых источников информацию о том, какие успехи уже достигнуты другими инженерами при решении именно задач визуализации фигур вращения. Писать о том, что такое компьютерная графика, не нужно. Это касается не только введения --- в пояснительной записке нужно писать {\bf именно о своей теме}. Не нужно <<лить воду>> и писать общие слова о том, как стремительно развивается область ИТ, до чего <<довёл прогресс>>, что <<современное человечество не может жить без компьютеров>> и т.д. Также необходимо отразить {\bf актуальность работы} и обосновать, почему потребовалось разрабатывать собственное ПО, а не использовать доступное. Далее приводятся цель и перечисляются задачи работы.

{\bf Цель работы } --- это то, ради чего разрабатывается программный продукт; ради чего проводится исследование. Это тот положительный эффект для конечного пользователя, который будет достигнут при использовании им нашей разработки. Например, мы разрабатываем клиент-серверное приложение для взаимодействия учеников и репетиторов. Цель такой работы --- не разработка ПО, а ускорение (упрощение) взаимодействия ученика и репетитора. 

\begin{tcolorbox}[colback=red!10, colframe=red!50!black, title={Пример неправильно сформулированной цели}]
	\par Разработка клиент-серверного приложения для взаимодействия ученика и репетитора.
\end{tcolorbox}
\begin{tcolorbox}[title={Пример правильно сформулированной цели}]
	\par Экономия времени и ускорение взаимодействия ученика и репетитора при проверке заданий и объяснении учебного материала с помощью клиент-серверного приложения.
\end{tcolorbox}

Рассмотрим предыдущий пример. Предположим, мы разрабатываем ПО для визуализации тел вращения, которое должно работать на платформе Arduino.

\begin{tcolorbox}[colback=red!10, colframe=red!50!black, title={Пример неправильно сформулированной цели}]
	\par Разработка программного обеспечения для визуализации тел вращения на платформе Arduino.
\end{tcolorbox}
\begin{tcolorbox}[title={Пример правильно сформулированной цели}]
	\par Визуализация тел вращения в условиях ограниченных вычислительных ресурсов на платформе Arduino.
\end{tcolorbox}

Задачи --- последовательность шагов, которые нужно выполнить для достижения цели. К примеру, для задачи визуализации тел вращения можно выделить следующие задачи:
\begin{enumerate}[label=\arabic*., wide]
	\item Поиск и сравнение существующих методов визуализации тел вращения неполигональными способами.
	\item Разработка алгоритма визуализации тел вращения без использования полигонов с учётом освещения и затенения в условиях ограниченных вычислительных ресурсов.
	\item Разработка архитектуры и программного обеспечения для визуализации тел вращения.
	\item Тестирование разработанного программного обеспечения для визуализации тел вращения.	
	\item Создание руководства пользователя разработанного программного обеспечения для визуализации тел вращения.
\end{enumerate}

 Таким образом, цель исследования или разработки следует связывать с конкретным ожидаемым эффектом, а разработку ПО рассматривать как средство (инструмент) его достижения. Под ожидаемым эффектом может пониматься, например, экономия времени пользователя, повышение удобства общения, уменьшение стоимости продукции, ускорение физического расчёта, экономия ресурсов предприятия, повышение точности моделирования, ускорение доставки товара, снижение трудозатрат и т.д.

Завершается введение кратким описанием структуры ВКР по главам. Объём введения --- 3-4 стр.

В первой главе {\bf <<Анализ состояния исследований и разработок в предметной области...>>} должны быть представлены: постановка задачи, актуальность работы, обоснование используемых технологий (стека технологий), описание (сравнение и обоснование) используемых методов, обзор существующих решений (аналогов) для решения поставленной задачи (подробный), краткий обзор предметной области.
\par Рекомендуется начинать первую главу с литературного обзора по заявленной теме: степень её разработанности, какие методы и алгоритмы уже предложены для решения поставленной  задачи, какие у них есть достоинства и недостатки, со ссылками на литературные источники или материалы в интернете. Если задача является новой, т.е. ранее не решалась, то можно писать о смежных задачах. 
\par Если работа имеет ярко выраженный математический характер, то постановка задачи должна быть выполнена в математической форме. В этом случае нужно написать в словесно-формульном виде, какие системы уравнений решаются с приведением всех переменных (с единицами измерения). Постановка прикладных задач может быть выполнена в словесной форме в виде перечисления методов, алгоритмов, архитектур, программ, интерфейсов и остальных компонентов, подлежащих разработке.
\par Теоретические сведения допускаются только в первой главе. Все последующие главы должны содержать только оригинальный материал и собственные разработки.
\par Рекомендуемая структура первой главы следующая:
\begin{enumerate}[label=\arabic*.]
\item Литературный обзор по разрабатываемой тематике.
\item Обзор существующих аналогов, методов и технологий разработки аналогичных программ.
\item Объект и предмет исследования.
\item Постановка задачи.
\item Практическая и теоретическая значимость.
\item Используемые методы и технологии разработки ПО.
\item Краткие теоретические сведения.
\end{enumerate}

Рекомендуемый объём первой главы --- 25-30 страниц.

Вторую главу {\bf <<Разработка архитектуры программного обеспечения>>} рекомендуется начинать с написания технического задания (ТЗ) на разработку программного обеспечения. Само ТЗ  при этом выносится в приложение А, а во второй главе указываются ссылки на него. В ТЗ должны быть изложены {\bf все} 
\begin{itemize}[label=$\bullet$, wide]
\item функциональные требования к ПО, 
\item требования к интерфейсу,
\item требования к надёжности,
\item требования к используемому стеку технологий,
\item требования к аппаратному обеспечению,
\item требования информационной безопасности.
\end{itemize}

ТЗ оформляется в соответствии с ГОСТ 19.201-78~\cite{gost19201}. 

Предполагается, что вторая глава пишется до непосредственной разработки ПО. Содержание этой главы не должно быть строго привязано к какой-либо технологии или языку программирования. В ней должна быть описана работа, которую обычно выполняет аналитик перед выдачей задачи программистам. Аналитик описывает взаимодействие модулей программного обеспечения на абстрактном уровне, не вникая глубоко в детали реализации на конкретных языках программирования. %Но ВКР выполняется самостоятельно, поэтому мы сами (с дипломным руководителем) являемся аналитиками и постановщиками задачи.
При описании архитектуры требуется использовать стандартизированные методики формализации предметной области (нотации UML, IDEF0, DFD, ER-диаграммы, блок-схемы, диаграммы сценариев и другие). 

Любое ПО должно быть декомпозировано, т.е. состоять из каких-то независящих друг от друга логических частей. Трудно представить себе сложную программу, которая состоит только из одной функции \texttt{main} внутри файла \texttt{main.cpp}, в которой реализован весь предъявляемый к ней функционал. Любая парадигма программирования предусматривает свой способ декомпозиции. В объектно-ориентирован\-ных языках (C++, Python, Java) ПО состоит из классов и методов, в процедурных (Си, Паскаль) --- из подпрограмм, в функциональных (Haskell) --- из чистых функций, в реляционных (SQL) --- из таблиц, в языках описания электронных схем (Veri\-log) --- из модулей. Даже в скриптовых языках текст делится на блоки. Во второй главе обязательно должна быть выполнена декомпозиция предметной области. Предположим, что в работе используется объектно-ориентированная парадигма программирования. В этом случае необходимо ввести подраздел {\bf <<Разработка структуры классов программного обеспечения>>} и сначала описать в нём взаимодействие классов в виде диаграммы классов. Далее для каждого класса нужно написать вложенный подраздел, в котором перечислить, из каких подпрограмм он состоит и что они выполняют. Похожим образом выполняется декомпозиция и в других стилях программирования.

Во второй главе также могут быть представлены:
\begin{itemize}[label=$\bullet$]
\item разработка математических методов и алгоритмов (с использованием формул и блок-схем);
\item оценка вычислительной сложности разработанных алгоритмов,  возможные способы их распараллеливания и оптимизации;
\item разработка структур данных (списков, матриц, графов и т.д.),
\item разработка структур баз данных (в виде диаграмм типа <<сущность-связь>>, ER-диаграмм),
\item разработка структур нейронных сетей (в виде графов или послойно),
\item разработка пользовательского интерфейса.
\end{itemize}

Рекомендуемый объём второй главы --- 20-25 страниц.

Третья глава {\bf <<Разработка алгоритмов и программного обеспечения>>} должна содержать подробное описание реализации ПО применительно к выбранным языкам и технологиям программирования. В этой главе должны быть приведены спецификации подпрограмм для каждого класса (модуля). 
\begin{tcolorbox}[title={Пример спецификации подпрограммы}]
	\par Спецификация функции \texttt{get\_even\_numbers}.
	\begin{enumerate}[label=\arabic*., wide]
	\item Заголовок: \texttt{int get\_even\_numbers(const int* a, int n, int* even)}.
	\item Назначение: записывает по адресу \texttt{even} чётные элементы массива \texttt{a} длиной \texttt{n} и возвращает длину массива \texttt{even}.
	\item Входные параметры: \texttt{a} --- указатель  на массив, \texttt{n} --- количество элементов массива \texttt{a}.
	\item Выходные параметры: \texttt{even} --- указатель на массив с чётными числами.
	\end{enumerate}
\end{tcolorbox}

Если классов и подпрограмм много, то для специфицирования нужно выбрать основные. 
В третьей главе могут быть также представлены:
\begin{itemize}[label=$\bullet$]
\item описание структур данных на выбранном языке программирования;
\item наиболее важные фрагменты программ с комментариями и пояснениями;
\item описание предложенных оригинальных программных решений;
\item программные решения для обеспечения информационной безопасности (хранение персональных данных и паролей, конфиденциальность и т.д.);
\item краткое описание использованных сторонних библиотек;
\item программные решения для оптимизации и распараллеливания разработанных алгоритмов;
\item оценка производительности, отказоустойчивости, метрологических и эргономических характеристик;
\item результаты тестирования;
\item руководство пользователя;
\item результаты внедрения;
\item оценка качества разработанного ПО.
\end{itemize}

Приложения, осуществляющие хранение и обработку критически важной информации (включая аутентификационные данные и персональную информацию), должны разрабатываться в соответствии с требованиями безопасной разработки ПО и обеспечивать защиту информации от несанкционированного доступа и утечек. 

Если руководство пользователя объёмное, то его рекомендуется вынести в отдельную главу.

Для научно-исследовательских задач должны быть приведены результаты вычислительных экспериментов на реальных и/или модельных данных.

Рекомендуемый объём третьей главы --- 30-40 страниц.

По согласованию с дипломным руководителем, в ВКР могут быть добавлены дополнительные главы. После основных глав следует заключение и список использованной литературы. В заключении перечисляются прямые результаты разработки --- преимущества разработанных алгоритмов и ПО над аналогами в плане скорости, функциональности, удобства и прочих характеристик.

\subsection{Иллюстративный материал}
К защите ВКР должен быть подготовлен иллюстративный материал в виде презентации, которая демонстрируется с помощью проектора. Презентация должна содержать:
\begin{enumerate}[label=\arabic*.]
	\item Титульный лист (на нём должны быть указаны без сокращения ФИО студента и руководителя, должность и учёная степень руководителя).
	\item Цель и задачи ВКР.
	\item Постановка задачи на разработку ПО (для научно-исследовательских задач должна быть в словесно-формульном виде).
	\item Актуальность работы и обоснование разработки.
	\item Сравнительный анализ существующих аналогов.
	\item Используемые технологии разработки, инструментальные, программные средства и библиотеки.
	\item Описание обрабатываемых данных, их формат и структура.
	\item Описание входных и выходных параметров программной системы.
	\item Описание математических моделей, методов и алгоритмов.
	\item Описание декомпозиции и архитектуры ПО (диаграммы классов, ER-диаг\-раммы, диаграммы потоков данных, диаграммы пользовательских сценариев, графы и послойные схемы нейронных сетей, блок-схемы и прочее).
	\item Описание системных требований (ОС, ПО, аппаратные требования).
	\item Методы обеспечения информационной безопасности разработанного ПО (конфиденциальность, денежные операции, хранение персональных данных, хэширование паролей и т.д.).
	\item Внешний вид программ.
	\item Результаты моделирования, проведения вычислительных экспериментов.
	\item Результаты тестирования, оценки производительности.
	\item Заключение: основные выводы, достигнутые преимущества разработанного ПО.
	\item Перечень публикаций по результатам выполнения ВКР.
\end{enumerate}

По согласованию с дипломным руководителем в презентацию можно включать и другие материалы ВКР. Не рекомендуется включать в презентацию фрагменты исходного текста программ, не имеющие большой смысловой нагрузки. Текст на слайдах должен быть написан чёрным цветом на светлом фоне, занимать всю доступную площадь и быть хорошо разборчивым, в том числе на картинках.


\section{ТРЕБОВАНИЯ К ОФОРМЛЕНИЮ ПОЯСНИТЕЛЬНОЙ ЗАПИСКИ}
Пояснительная записка к ВКР может быть оформлена в текстовом редакторе или в издательской системе \LaTeX. Для автоматического форматирования пояснительных записок под единые требования на кафедре ПОВТАС разработан стилевой файл \texttt{bstunote.sty} для текстового процессора \LaTeX. Данный файл совместим c компиляторами PDFLaTeX, XeLaTeX, LuaLaTeX. Ниже представлены требования к оформлению пояснительной записки и руководство по использованию пакета \texttt{bstunote}.
\subsection{Параметры страницы}

Пояснительная записка должна быть выполнена на листах формата A4. Для ВКР специалиста и бакалавра размеры полей должны быть заданы следующими:
\par левое --- не менее $27$ мм,
\par правое --- около $10$ мм,
\par верхнее --- около $10$ мм,
\par нижнее --- не менее $21$ мм.


Перечисленные параметры следует задавать стандартной командой из пакета \texttt{geometry}:
\begin{center}
	\small\verb|\usepackage[a4paper, left=30mm, right=9mm, top=9mm, bottom=24mm]{geometry}|
\end{center}

Левое поле должно быть не менее $3$ см, чтобы при прошивке обложка диплома не скрывала текст, как показано на рисунке~\ref{fig:wrongvkr}. Если предполагается качественная прошивка, то левое поле можно уменьшить до 23 мм.
Остальные поля нужно задать так, чтобы текст гармонично вписывался внутрь рамки. К примеру, отступить от рамки со всех сторон $3$ мм. Чтобы посмотреть границы текста, нужно при подключении пакета \texttt{geometry} добавить опцию \texttt{showframe}.
\begin{figure}[h!]
	\centering
	\includegraphics[width=0.5\textwidth]{figures/wrongvkr.png}
	\caption{Образец неправильно прошитого диплома. Авторский материал}
	\label{fig:wrongvkr}
\end{figure}


Пакет \texttt{bstunote} автоматически подставляет <<большие>> рамки (по форме~2 из ГОСТ 2.104--2023~\cite{gost2104}) на первой странице каждого раздела и <<маленькие>> (по форме~2а) на следующих страницах. 
Здесь нижняя граница (\texttt{bottom}) увеличена до $24$ мм, исходя из параметров чертёжного штампа по форме 2а, высота которого равна $15$ мм.

Нужно учитывать, что положение рамки на бумаге после печати может отличаться от того, мы видим на экране. Чтобы оно совпадало, нужно обязательно задать в настройках масштаб печати, равный $100\%$. В некоторых pdf-просмотрщиках этот масштаб может называться: <<Реальный размер>>, <<По размеру бумаги>>, <<Фактический размер>>.

Чтобы отключить рамки, нужно при подключении пакета \texttt{bstunote} сбросить флаг \texttt{drawstamps}:
\begin{quote}
	\small\verb|\usepackage[drawstamps=false]{bstunote}|
\end{quote}

В магистерской диссертации рамки отсутствуют, а параметры полей рекомендуется задавать следующей командой:
\begin{quote}
\small
\begin{verbatim}
\usepackage[a4paper, left=30mm, right=10mm, top=10mm, 
									bottom=10mm]{geometry}
\end{verbatim}
\end{quote}

\subsection{Титульный лист, задание на ВКР, лист проверки заимствований}
Начало пояснительной записки включает следующие листы: 
\par 1 лист --- титульный лист, не нумеруется.
\par 2 лист --- задание на ВКР, не нумеруется. Задание на ВКР печатается с двух сторон. То есть календарный план должен быть напечатан с обратной стороны.
\par 3 лист --- результаты проверки электронной версии ВКР на заимствования, не нумеруется. Этот лист тоже обязательно вшивается в диплом.

\par Далее следует сквозная нумерация, начиная с номера <<4>>.
\par 4 лист --- лист определений, сокращений, обозначений. Этот лист необязательный. Он нумеруется цифрой <<4>>.
\par Отзыв руководителя и справка о результатах проверки текста ВКР на наличие заимствований в системе АНТИПЛАГИАТ.ВУЗ вкладываются в уголок на корочке диплома. В уголок магистерской диссертации также вкладывается рецензия от специалиста. Рецензия должна быть подписана и заверена печатью организации, которая её предоставила. Если уголок на корочке отсутствует, то его необходимо самостоятельно приклеить.

Нумерация страниц основного текста и приложений – сквозная (нумеруются все страницы, до последней страницы приложения), номер страницы указывается в штампе в графе <<Лист>>.

\subsection{Параметры основного текста}
При использовании компилятора XeLaTeX или LuaLaTeX разрешается использовать отечественные шрифты с засечками семейства PT~Astra. Если используется компилятор PDFLaTeX, то можно использовать для вёрстки стандартные шрифты с засечками семейств Computer Modern или ParaType. Размер шрифта должен составлять 14 пунктов, но допускается его уменьшение до 13 или 12 пунктов. Размер шрифта задаётся в преамбуле при подключении базового класса \texttt{extarticle} следующей командой:
\begin{quote}
\small\verb|\documentclass[14pt]{extarticle}|
\end{quote}

Основной текст везде выравнивается по ширине. Красная строка равна 1,25~см, междустрочный интервал --- полуторный. Эти параметры задаются автоматически. Абзацный отступ, шрифт и междустрочный интервал должны быть везде одинаковыми. Начертание --- прямой шрифт (не курсив, не полужирный). Полужирным шрифтом разрешается выделять только заголовки или отдельные слова, на которые нужно заострить внимание. Выделять полужирным шрифтом или курсивом целые предложения или даже абзацы не допускается. 

\subsection{Параметры рубрикации}
Заголовки структурных элементов (содержание, введение, основные главы, заключение, список литературы) выравниваются по левому краю с красной строки, печатаются прописными буквами и полужирным шрифтом. Данные структурные элементы начинаются с нового листа.

Нумеруются только основные главы. Точка после номера заголовка раздела (главы), подраздела второго и третьего уровней не ставится~\cite[раздел 6.5]{gost2105}.
Если раздел или подраздел состоит из одного пункта, он также нумеруется.
В конце заголовка точки не должно быть. Междустрочный интервал перед заголовком должен быть двойной, после заголовка --- полуторный.
Переносить слова по слогам в заголовках нельзя.
Заголовки подразделов следует начинать с прописной буквы. Заголовки подразделов четвёртого уровня изначально не предусмотрены. При необходимости, следует писать их просто без номера полужирным шрифтом, не вынося в содержание. Подраздел не должен занимать меньше половины страницы. Если подраздел маленький, то рекомендуется объединить его с разделом верхнего уровня. Раздел не должен заканчиваться перечислением, таблицей, рисунком. В конце каждой главы нужно написать подраздел <<Вывод по $n$-ой (первой, второй, третьей и т.д.) главе>> без нумерации и не вынося его в содержание.

Для создания заголовков нужно использовать стандартные команды:
\begin{quote}
\small
\begin{verbatim}
\section*[ВВЕДЕНИЕ]{ВВЕДЕНИЕ} % Заголовок I уровня (глава) без номера
\section{ОПИСАНИЕ ПРЕДМЕТНОЙ ОБЛАСТИ}            % Первый уровень
\subsection{Методы решения нелинейных уравнений} % Второй уровень
\subsubsection{Метод Ньютона}                    % Третий уровень
\par\textbf{Математический вывод метода Ньютона} % Четвёртый уровень
\end{verbatim}
\end{quote}

Представленные команды секционирования уже настроены. Команда \linebreak \verb|\section| определена таким образом, что при её обнаружении во входящем потоке инициализируется процесс рисования рамок со штампами на всех страницах. Название текущего раздела при этом сохраняется и становится доступным через команду \texttt{\textbackslash theStampSection}. Данная команда затем используется для автоматической подстановки в штампы названия текущего раздела (главы). В особых случаях, когда название главы не вмещается в графу штампа, можно вручную задать требуемый текст  командой \texttt{\textbackslash StampSection} после команды \verb|\section|, указав в ней размер шрифта или добавив перенос по слогам в названии заголовка:

\begin{quote}
\small
\begin{verbatim}
\StampSection{\fontsize{12.5pt}{10pt}\selectfont
	ДЛИННЫЙ ЗАГОЛОВОК, КОТОРЫЙ НЕ ПОМЕЩАЕТСЯ В ГРАФУ, С УМЕНЬШЕННЫМ РАЗМЕРОМ
	ШРИФТА ИЛИ ПЕ\-РЕ\-НО\-СОМ ПО СЛО\-ГАМ В НУЖНЫХ МЕСТАХ}
\end{verbatim}
\end{quote}

Рамка со штампом генерируется в последнюю очередь --- после того, как весь остальной текст на странице скомпонован. Не следует подключать пакеты, которые будут перенастраивать заголовки, например, \texttt{titlesec}. Рамки в этом случае нарисованы не будут.

\subsection{Оформление иллюстраций}
На все рисунки должны быть ссылки в основном тексте записки, причём они должны предшествовать самим рисункам.
Название рисунка выравнивается по центру под рисунком. Подписи к рисункам должны быть сделаны шрифтом, размер которого составляет не менее 12 пунктов.
Собственные рисунки отмечаются добавлением словосочетания <<авторский материал>>, заимствованные рисунки подписываются со ссылкой на источник литературы в квадратных скобках.
Слово <<рисунок>> перед самой ссылкой сокращать не нужно.

\begin{enumerate}[label=\arabic*., wide]
\item На рисунке~\ref{fig:harebo} изображён заяц Бо, который программирует генератор идеального изображения.
\item Используемый алгоритм (рисунок 2.3) генерации идеального изображения реализован с помощью нейронных сетей глубокого обучения.
\item Представленный на рисунке 3.1 алгоритм распознавания лексем используется во многих интерпретаторах.
\end{enumerate}
\end{tcolorbox}

\begin{figure}[h!]
	\centering
	\includegraphics[width=0.7\textwidth]{figures/hareBo.png}
	\caption{Заяц программирует на крыше [1]}
	\label{fig:harebo}

Номер рисунка начинается с номера главы, т.е. в первой главе рисунки нумеруются как <<Рисунок~1.1; Рисунок~1.2;\dots>>, во второй --- <<Рисунок~2.1; Рисунок~2.2;\dots>> и т.д.
Если рисунок занимает более половины страницы, то его необходимо перенести в приложение.
Рисунки в приложениях нумеруются прописными буквами русского алфавита, как написано ниже.
\begin{tcolorbox}[title={Примеры подписей для рисунков в приложениях}]
\small

\par Рисунок A.2 -- <Название второго рисунка в Приложении А>. Авторский материал
\par Рисунок Б.1 -- <Название первого рисунка в Приложении Б>. Авторский материал
\end{tcolorbox}

Требования к рисункам:
\begin{enumerate}[label=\arabic*., wide]
\item Растровые рисунки должны иметь разрешение не менее 300 dpi. Толщина самой тонкой линии после печати --- не менее $0.2$ мм (как в тетради в клетку).
\item Надписи на рисунках должны быть выполнены на русском языке. Английские названия идентификаторов должны дублироваться в скобках на русском языке. На графиках нужно подписать оси (название и единицы измерения параметров), изобразить числовую сетку. Надписи на рисунках должны быть хорошо различимы после печати.
\item Основные линии должны быть нарисованы чёрным цветом. Разрешается дополнительно использовать другие цвета, хорошо различимые после чёрно-белой печати. Цветные рисунки должны быть распечатаны цветными красками, если это важно в контексте изложения. 
\item Цвет фона на схемах, диаграммах, графиках --- белый.
\item Снимки экранов с интегрированных средств разработки не допускаются.
\end{enumerate}


\subsection{Оформление таблиц}
Название таблицы размещается непосредственно над таблицей, выравнивается по левому краю и имеет вид: <<Таблица 1.1 -- Название таблицы>>. 
Если таблица помещается на листе, то разрывать её не следует. Если таблица не умещается на листе, то её нужно разделить на части. Продолжение таблицы при этом переносится на следующую страницу, в правом верхнем углу которой необходимо написать <<Продолжение таблицы 1.1>>. Строку с заголовком при этом нужно повторить.
Ссылки на таблицы в основном тексте оформляются так же, как на рисунки.
Колонки таблицы должны быть растянуты на всю рабочую ширину \texttt{\textbackslash textwidth}. Рекомендуется создавать таблицы с использованием пакета \texttt{longtable} или аналогичного, который поддерживает многостраничные таблицы.

\subsection{Оформление формул}
Номер формулы пишется в круглых скобках и выравнивается по правому краю, если на формулу есть ссылка в тексте. Если на формулу ссылки нет, то она не нумеруется. У формул, как и у рисунков, номер начинается с номера главы. Далее после точки следует номер формулы непосредственно внутри главы. Таким образом, в первой главе формулы имеют номера 1.1, 1.2, 1.3 и т.д., во второй~--- 2.1, 2.2, 2.3 и т.д.


\begin{tcolorbox}[title={Пример оформления формулы}]
\par Формула Планка для спектральной плотности излучения абсолютно чёрного тела имеет вид:
\begin{equation}
\label{eq:blackbody}
I(\nu, T) = \frac{2h\nu^3}{c^2} \cdot \frac{1}{e^{\frac{h\nu}{kT}} - 1},
\end{equation}
где
\begin{itemize}[label=$\bullet$]
	\item $I(\nu, T)$ --- спектральная плотность излучения (Вт/(м²·Гц),
	\item $h$ --- постоянная Планка, равная приблизительно $6,626 \times 10^{-34}$ Дж·с,
	\item $\nu$ --- частота излучения (Гц),
	\item $c$ --- скорость света в вакууме (около $3 \times 10^8$ м/c),
	\item $k$ --- постоянная Больцмана, равная приблизительно $1,381 \times 10^{-23}$ Дж/К,
	\item $T$ --- абсолютная температура тела (K).
\end{itemize}

\par Формула~\eqref{eq:blackbody} описывает распределение энергии излучения абсолютно чёрного тела в зависимости от частоты $\nu$ и температуры $T$.
\end{tcolorbox}

Любая формула является частью предложения, поэтому нужно правильно расставлять знаки препинания перед ней и после неё. Если несколько формул следуют друг за другом, то они тоже должны разделятся знаками препинания. В написанном примере формула заканчивается запятой, потому что далее предложение продолжается словом <<где>>. Значит, перед словом <<где>> абзацный отступ не нужен. Все переменные, которые есть в формуле, должны быть раскрыты в тексте, т.е. после прочтения должно быть понятно, что каждая переменная в формуле означает. Формулы нельзя разрывать на несколько строк где попало. Формулы переносятся на следующую строку только знаками <<=>>, <<+>>, <<-->> с повторением этого знака в новой строке. Внутри предложений математические переменные тоже должны быть набраны как формулы, т.е. с использованием математического режима \verb|$...$|.

Образцы правильно оформленных формул рекомендуется смотреть в книгах по математике или научных журналах. К примеру, очень хорошо оформляются формулы в журнале <<Вычислительные методы и программирование>>, все выпуски которого доступны на сайте \href{https://num-meth.ru/index.php/journal/issue/archive}{https://num-meth.ru/index.php/journal/issue/archive}.

\subsection{Оформление списков}
Списки (перечни или перечисления) бывают двух видов --- маркированные и нумерованные. В маркированном списке каждый пункт маркируется символом дефиса <<->> или кругом <<$\bullet$>>, <<$\circ$>>. В нумерованном списке пункты нумеруются строчными буквами русского алфавита или арабскими цифрами. После буквы записывается круглая скобка.
Каждый пункт списка должен начинаться с абзацного отступа. Если пункты списка длинные, то его нужно выравнивать на всю ширину с использованием опции \texttt{wide}. Если пункты списка короткие, то опция  \texttt{wide} не нужна. Тогда все строки запишутся с отступом и визуально список не будет иметь <<хвостов>>.
 %Нумерованный список используется в том случае, если требуется ссылка на какой-либо пункт из этого списка.

В списках пункты разделяются запятыми, если сами пункты короткие; точками с запятой, если пункты содержат запятые; точками, если пункты содержат целые предложения. 
Список должен заканчиваться точкой.

Внутри пакета \texttt{bstunote} окружения \texttt{itemize} (маркированные списки) и \linebreak \texttt{enumerate} (нумерованные списки) настроены на соответствие ГОСТ~Р~2.105--2019 \cite[раздел 6.7]{gost2105}.

\begin{tcolorbox}[title={Пример маркированного списка}, before upper={\setlength{\parindent}{1.25cm}}]
\par Виды компьютерной графики:
\begin{itemize}
	\item растровая,
	\item векторная,
	\item фрактальная.
\end{itemize}
\end{tcolorbox}

\begin{tcolorbox}[title={Пример нумерованного списка}, before upper={\setlength{\parindent}{1.25cm}}]
\par Любое число, хранимое в оперативной памяти может быть
\begin{enumerate}
\item целым различной разрядности:
	\begin{enumerate}
		\item 8-разрядное (\texttt{char}),
		\item 16-разрядное (\texttt{short}),	
		\item 32-разрядное (\texttt{int}),	
		\item 64-разрядное (\texttt{long long});
	\end{enumerate}
\item вещественным различной точности: 
	\begin{enumerate}
		\item одинарная точность (\texttt{float}),
		\item двойная точность (\texttt{double});
	\end{enumerate}
\item двоично-десятичным в одном из двух форматов:
	\begin{enumerate}
		\item упакованное,
		\item неупакованное.
	\end{enumerate}
\end{enumerate}
\end{tcolorbox}

Правила оформления списков рекомендуется смотреть в \href{https://vk.com/wall-36387183_1421}{справочнике Лопатина~В.В.}~\cite[с. 320]{lopatin}, а также в статье Лотош~Л.С. <<\href{https://delo-press.ru/journals/documents/oformlenie-dokumentov/34821-pravila-oformleniya-perechney/}{Правила оформления перечней}>>~\cite{lotosh}.

\subsection{Оформление листингов}
В основные главы записки можно вставлять небольшие фрагменты программ до 20 строк. Эти фрагменты называются листингами. Если листинг занимает больше 20 строк, то нужно перенести его в приложение и сделать в тексте ссылку на него. Все листинги должны быть подписаны. Название листинга записывается перед листингом и выравнивается по левому краю. Ссылка на листинг должна предшествовать самому листингу. Нельзя вставлять текст программы как картинку. 
В листингах строки программы должны быть пронумерованы, пустые строки не допускаются. Комментарии должны быть написаны с прописной буквы без грамматических ошибок на русском языке.  Обязательные параметры листингов:
\par тип шрифта --- моноширинный,
\par размер шрифта --- не более 10 пт., 
\par отступ после открытия операторной скобки (по англ. indentation) --- два пробела,
\par фон --- светлый.


Остальные параметры (подсветка, семейство шрифта, цвета и др.) выбираются на усмотрение автора.
Для оформления листингов рекомендуется использовать стандартный пакет \texttt{listings} или более современный -- \texttt{minted}.

\begin{tcolorbox}[title={Примеры подписей для листингов}]
	\small
	\par Листинг 1.1 -- <Заголовок первого листинга в первой главе>
	\par Листинг 1.2 -- <Заголовок второго листинга в первой главе>
	\par Листинг 2.1 -- <Заголовок первого листинга во второй главе>
	\par Листинг А.1 -- <Заголовок первого листинга в приложении А>
	\par Листинг А.2 -- <Заголовок второго листинга в приложении А>
\end{tcolorbox}

\begin{tcolorbox}[title={Пример ссылки на листинг}]
	В листинге~\ref{lst:inverse} представлена функция обратной перестановки битов, широко используемая в алгоритмах быстрого преобразования Фурье.
\end{tcolorbox}

\begin{lstlisting}[caption={Реализация обратной перестановки битов на языке Python}, label={lst:inverse}, language=Python]
# Обратная перестановка битов
def inverse(a, m):
	r = 0
	while m:
		r = 2 * r + a % 2
		a //= 2
		m //= 2
	return r
\end{lstlisting}

Если в ходе изложения требуется объяснить небольшой фрагмент программы, который невозможно оформить в полноценный листинг, то  рекомендуется использовать окружение \verb|\begin{verbatim}...\end{verbatim}|.

\begin{tcolorbox}[title={Пример использования окружения \texttt{verbatim}}]
\par Добавим  во внутренний цикл функции растеризации вычисление барицентрических координат $h_0$, $h_1$, $h_2$ для текущего пикселя $(x, y)$:
\begin{quote}
\small
\begin{verbatim}
float S = (y1 - y2) * (x0 - x2) + (x2 - x1) * (y0 - y2); // Площадь
float h0 = ((y1 - y2) * (x - x2) + (x2 - x1) * (y - y2)) / S;
float h1 = ((y2 - y0) * (x - x2) + (x0 - x2) * (y - y2)) / S;
float h2 = ((y0 - y1) * (x - x1) + (x1 - x0) * (y - y1)) / S;
\end{verbatim}
\end{quote}
\par Тогда координата $z$ точки (текущего пикселя) на треугольнике вычисляется в результате интерполяции координат $z$ трёх вершин треугольника:
\begin{quote}
	\small\verb|float Z = h0 * z0 + h1 * z1 + h2 * z2; // Глубина пикселя|
\end{quote}
\end{tcolorbox}

Названия переменных, методов, классов, полей таблиц БД и прочих идентификаторов, полученных на этапе проектирования собственного ПО должны быть набраны \texttt{моноширинным} шрифтом. Внутри основного текста не нужно записывать круглые скобки после названий методов.

\begin{tcolorbox}[title={Пример использования моноширинного шрифта внутри текста}]
Метод \texttt{OnScopeMouseMove} вызывается при перемещении мыши в пределах основной рамки \verb|scope| и принимает координаты курсора в качестве аргументов \texttt{xpos} и \texttt{ypos}.
\end{tcolorbox}

 В пояснительной записке и разработанных программах числовые результаты требуется выводить с числом знаков, не превышающим точность применяемого метода и допускаемую величину погрешности.

\subsection{Оформление списка литературы}

Список литературы оформляется в соответствии с ГОСТ Р 7.0.100--2018~\cite{gost70100} и ГОСТ Р 7.0.5--2008~\cite{gost705}.
На все источники в списке литературы должны быть ссылки в тексте.
Ссылки на литературные источники должны нумероваться в порядке их появления в тексте, начиная с единицы. Примеры ссылок на источники:
\par <<\dots в статье [2] описан метод решения\dots>>,
\par <<В работах [3,4] опубликованы результаты\dots>>.

Если литературный источник доступен в интернете, то ссылка на него в самом списке литературы должна быть кликабельной, чтобы легко можно было перейти по ней и открыть.

\subsection{Требования к литературному стилю}

Текст пояснительной записки не должен содержать грамматических ошибок (синтаксических, пунктуационных и других). Все предложения должны быть согласованы между собой, быть ясными и понятными. Пояснительная записка должна быть написана на русском языке в строгом научном стиле. Разрешается использовать только те слова русского языка, которые являются устоявшимися и определены в словарях русского языка (научно-техническом, толковом).

Нельзя начинать предложение с английского слова, названия идентификатора, математического обозначения или числа.

Перед английскими словами нужно пояснять, что они означают.
Например, <<метод beforeEach>>, <<технология REST API>>, <<API-функция>>, <<HTTP-запрос>>, <<паттерн MVC>>, <<язык Python>>, <<модуль CRM>>, <<переменная file\_name>>, <<СУБД Postgre\-SQL>>.
\begin{tcolorbox}[colback=red!10, colframe=red!50!black, title={Пример неграмотно построенного предложения}]
	\par \texttt{addition} находится внутри \texttt{TComplex} и написан на C++ с использованием MVC.
\end{tcolorbox}
\begin{tcolorbox}[title={Пример грамотно построенного предложения}]
	\par Метод \texttt{addition} находится внутри класса \texttt{TComplex} и написан на языке C++ с использованием шаблона MVC.
\end{tcolorbox}

Слова, которых нет в научно-техническом словаре (а по сути, в русском языке), использовать не разрешается. К примеру, слова <<хедер>>, <<футер>>, <<стор>>, <<баг>>, <<продакшн>>, <<бэкап>>, <<батч>>, <<скриншот>>, <<инстанс>>, <<логгер>>, <<краш>>, <<эндпоинт>>, <<фронтенд>>, <<дашборд>> и т.д.  нужно заменять русскоязычными аналогами, используя словарь синонимов. Пояснительная записка к ВКР должна быть оформлена на русском языке в научном стиле, а не звучать как речь настоящего <<айтишника>>, переевшего англицизмов. Если записка содержит англицизмы или сленговые выражения, то она возвращается на полную переработку.

\begin{tcolorbox}[colback=red!10, colframe=red!50!black, title={Пример неграмотно построенного предложения}]
	\par Баги на фронтенде, которые улетят в прод после релиза в сторе, приведут к полному эпик-фейлу, потому что тимлид заапрувил мерж-реквест, скипнув регрессию.
\end{tcolorbox}
\begin{tcolorbox}[title={Пример грамотно построенного предложения}]
	\par Ошибки в клиентской части, которые попадут в рабочую версию после публикации в магазине приложений, приведут к полному провалу, так как руководитель команды утвердил внесение изменений, пропустив этап регрессионного тестирования.
\end{tcolorbox}

Словари русского языка, в том числе словарь синонимов, доступны на сайте \href{https://gufo.me}{https://gufo.me}.

Букву <<ё>> лучше не заменять на <<е>>, иначе теряется смысл некоторых слов. Помним, что от буквы <<ё>> зависит \textbf{передохнем} мы или \textbf{передохнём}.

Не следует путать дефис <<->> и тире <<--->> в предложениях.

\section{Листинги разработанных подпрограмм для выполнения быстрого преобразования Фурье}

\begin{lstlisting}[caption={Реализация алгоритма БПФ с прореживанием по времени, обратной перестановкой битов и дополнительным массивом на языке C++}, label={lst:bpfalgo}, language=C++]
	void БПФ С ПЕРЕСТ БИТОВ И ВТОРЫМ МАССИВОМ(complex<double>* S, int N, complex<double>* A, int R, int d, double dk=0)
	{
		int l, i, j1, j2, r1, r2, m, NR = N*R, k, e;
		double angle;
		for (i=0; i < NR; i++)
		{
			k = inverse(i % N, N-1);
			A[i] = S[k];
		}
		complex<double>* B = new complex<double>[NR], W;
		l = N; m = R;
		while(l > 1)
		{
			for (i=0; i < NR/2; i++)
			{
				j1 = 2*i;	j2 = 2*i + 1;
				r1 = i;		r2 = i + NR/2;
				k = j1 / l;
				e = k * l;
				angle = -PI * (k + dk) / m;
				W = polar<double>(1, d * angle);
				W = W * A[j2];
				B[r1] = A[j1] + W;
				B[r2] = A[j1] - W;
			}
			memcpy(A, B, sizeof(complex<double>) * NR);
			l = l >> 1;
			m = m << 1;
		}
		delete []B;
	}
\end{lstlisting}
