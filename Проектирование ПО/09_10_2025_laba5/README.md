# Необходимая команда

Для разработки достаточно одного человека. У проекта нет бюджета, выхода на 
крупный рынок не планируется. Это pet-проект, который не будет нести никакой
бизнес пользы. Однако, если предположить, что этот проект действительно будет
выходить на средне-высокие охваты, будет приносить пользу и разрабатываться в большой команде, нам понадобятся:
* Лид x 2 - контроль за кодом, реализация сложных механизмов.
* Архитектор x 2 - проектирование архитектуры сервиса.
* Фронтенд-разработчик x 4 - вёрстка и отладка анимации, написание фронтовой бизнес-логики, юнит тестов.
* Бекенд-разработчик x 4 - реализация бекенд бизнес-логики, подключение и настройка интеграций, реализация контроллеров.
* Архитектор базы данных - реализация базы данных, разбиение задачи на высокоуровневые слои домена, формирование и оптимизация сложных запросов, кеширование запросов, индексация.
* DevOps - настройка CI/CD, окружения, подключение интеграций
* DevSecOps - подключение статических анализаторов для выявления угроз безопасности.
* ИБ x 2 - выявление возможных угроз приложения, составление отчётов безопасности, предложения по устранению ошибок безопасности, поддержка безопасности приложения на соответствующем уровне.
* UX/UI дизайнер x 2 - проработка внешнего вида приложения, анализ и сбор реакции пользователей, подготовка дизайна для вёрстки.
* Автотестировщики x 2 - программирование автотестов, составление тестейсов, составление отчётов.
* Функциональные тестировщики x 3 - составление тесткейсов, ручной прогон тестируемого продукта, составление отчётов.
* Системный аналитик - составление карты требований для сервиса, матрицы доступа.
* Технический писатель - составление документации по работе с сервисом, API сервиса.
* Продуктный менеджер - общение с заказчиком, передачач требований системному аналитику, настройка окружения и отслеживание эпиков.

# Описание

Приложение направлено на сопровождение и отслеживание музыкального трека.

Необходимые фичи:
* Ведение нескольких проектов и групп. У группы может быть название и обложка. Также можно будет пригласить пользователя в проект на позицию редактирования проекта и его данных. Не версионируется.
* Ведение профилей авторов. Важно отметить, что автор != пользователь. Считайте, что пользователь — это менеджер. Профиль автора может включать изображения, ФИО или псевдоним. Не версионируется.
* Возможность создания песен. Песня содержит в себе:
* Статус (черновик, в разработке, актуально, архив) — версионное
* Название - версионное
* Слова - версионное
* Описание — версионное
* Комментарии
* BPM - версионное
* Прикрепление автора или других проектов. Во втором случае песня будет прорастать и у другого проекта в режиме read-only. За автором или коллективом будет прикрепляться - версионное
* Аудиозаписи - версионное
* Изображения - версионное
* Прочие файлы - версионное
* Публичность — версионное (какие-то данные мы не захотим показывать, например)
* Права на редактирование с прикреплением роли

* Пользователи должны иметь возможность создавать быстрый плейлист который будет доступен другим пользователям. Плейлист может быть публичным и непубличным (указать, кто может слушать). Публичный плейлист может содержать в себе только публичные треки. Мы можем также указывать какую конкретную версию трека мы хотим опубликовать. Должна быть и доступна привязка к последней версии.
* Проект также должен включать в себя продвинутый плеер. Обычные функции: проигрывание, пауза, включить следующий трек. Также у плеера должен быть в наличии эквалайзер чтобы «на ходу» иметь возможность мастеринга трека (отдельный трек и весь эквалайзер в целом). Ещё одной фичей продвинутого плеера — возможность проигрывать треки одновременно. Для обеспечения такой возможности рядом с каждым треком должна стоять точка «продолжить с...». Кроме контролера «пауза» должен появиться контролер «стоп»
* Ролевая модель на уровне портала: User, Manager, Composer, Admin
* Ролевая модель на уровне проекта, песни, плейлиста: User, Viewer, Editor, Owner
* Дальнейшая потенциальная интеграция с сервисами публикации треков: ?

Итого по страницам:
* Домашняя страница с группами (в приоритете доступные для редактуры и отмеченные), авторами (в приоритете доступные для редактуры а также отмеченные), плейлистами (в приоритете доступные для редактуры а также отмеченные)
* Страница группы или проекта, в которой лежат песни в которых они участвовали а также доступные плейлисты с ними (реюз компонента с плейлистами, но с доп. фильтром на группу?)
* Страница песни (реюз компонента с плейлистами, но с доп. фильтром на песню)
* Страница плейлиста
* Страница автора (реюз компонентов группы и песни)
