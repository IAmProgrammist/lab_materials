Архитектор ПО - специалист, отвечающий за высокоуровневую структуру системы — её компоненты, их взаимодействие, ключевые нефункциональные требования (производительность, масштабируемость, надёжность, безопасность и т. п.).

Проектировщик ПО - специалист, фокусирующийся на проектировании модулей/подсистем в рамках заданной архитектуры. Занимается детальной структурой, алгоритмами, интерфейсами, схемами данных.

# Структуры
## Слоистая

• Суть: система разделена на слои (UI, бизнес-логика, доступ к данным и т.д.). Каждый слой взаимодействует преимущественно с соседним.
• Когда: классические корпоративные приложения, когда нужна чёткая разделённость ответственности.
• Плюсы: простота понимания, разделение ответственности, тестируемость.
• Минусы: может вести к монолитной структуре; затруднена масштабируемость по функциям; риск «тонкого» бизнес-слоя.
• Технологии: Spring (Java), ASP.NET, любые фреймворки MVC.

## Клиент‑сервер

• Суть: разделение на клиентов (пользовательский интерфейс) и сервер(ы) (логика, данные).
• Когда: веб-приложения, мобильные приложения.
• Плюсы: централизованное управление, безопасность данных на сервере.
• Минусы: точка отказа на сервере (если не реплицировать), сетевые задержки.
• Технологии: HTTP, REST, WebSocket.

## Монолит

• Суть: все компоненты в одном развертываемом артефакте/процессе.
• Когда: простые приложения, ранние стадии проекта, малые команды.
• Плюсы: простая разработка и отладка, меньше сетевого оверхеда.
• Минусы: сложность поддержки при росте, трудности с независимым масштабированием и деплоем.
• Технологии: любой фреймворк в монолитном развёртывании.

## Микросервисы

• Суть: система разбита на множество независимых сервисов, каждый со своей ответственностью, данными и циклом деплоя.
• Когда: большие распределённые системы, необходимость независимого развития и масштабирования.
• Плюсы: независимый деплой, масштабирование по сервисам, устойчивость к изменениям, технологическая свобода.
• Минусы: сложность оркестрации, распределённая трассировка, управление консистентностью, эксплуатационные затраты.
• Технологии: Docker, Kubernetes, gRPC, REST, Kafka, Spring Boot, Istio.

## Событийно‑ориентированная

• Суть: компоненты обмениваются событиями; реактивная модель обработки изменений состояния.
• Когда: асинхронная интеграция, высокий уровень распределённости, реактивные системы.
• Плюсы: слабая связность, масштабируемость, хороша для асинхронной обработки.
• Минусы: сложнее гарантия упорядоченности и доставки; сложнее отладка и тестирование.
• Технологии: Kafka, RabbitMQ, Amazon SNS/SQS.
